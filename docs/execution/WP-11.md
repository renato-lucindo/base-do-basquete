# WP-11 — Desempenho e cache condicionado

## Estado

`READY TO MERGE`: metas, benchmark SQL representativo, benchmark HTTP reproduzível, advisors, decisão de cache, gate e preview da PR #16 aprovados.

## Metas e volume

- Páginas públicas: p50 menor ou igual a 1.000 ms e p95 menor ou igual a 1.500 ms, medidos do host autorizado até o Worker.
- Agregação SQL avançada: até 250 ms no projeto Supabase atual.
- Volume representativo de uma edição da primeira temporada: 250 jogos, 240 atletas, 6.000 escalações e 24.000 linhas atleta/período.

## Evidências

- Benchmark SQL temporário, sem persistência: simples 158,089 ms; avançado 196,174 ms; ambos retornaram 240 atletas.
- Planos reais no staging: estatísticas da competição em 0,644 ms para 2 atletas; jogo FIBA em 2,032 ms para 20 atletas.
- Preview da PR #15, 3 aquecimentos e 30 amostras por rota, navegação com query única:
  - estatísticas avançadas: p50 318 ms, p95 711 ms, média 356,1 ms;
  - detalhe de jogo FIBA: p50 374 ms, p95 597 ms, média 405,8 ms.
- Advisors: nenhum item acionável novo. Permanecem somente índices ainda sem uso no pequeno staging, RLS sem policy no schema privado por desenho e proteção de senha vazada dependente de plano pago.
- Preview da PR #16: página de estatísticas avançadas e jogo FIBA 5205822/IVV 93×39 renderizados com os dados esperados.
- Head `88135ca`: `gate`, `database`, `upload` e `analyze` aprovados. A primeira execução de `database` identificou corretamente que o benchmark opt-in estava sob `supabase/tests/`; ele foi movido para `supabase/benchmarks/` e a segunda execução passou.

## Decisão

Cache não foi adicionado: todas as metas foram atendidas com margem, e o custo de invalidação após súmula/importação seria maior que o benefício na primeira temporada. A arquitetura futura e os gatilhos de reavaliação estão registrados em `docs/decisions/0003-cache-conditioned-by-measurement.md`.

## Reprodução

- Banco: executar `supabase/benchmarks/statistics_benchmark.sql` em staging; o script usa apenas objetos temporários e encerra com rollback. O arquivo fica fora de `supabase/tests/` para não ser interpretado como pgTAP pelo `supabase test db`.
- HTTP: executar `npm run benchmark:public -- <preview-url> 30`. O script exige HTTPS e bloqueia o Worker de produção por padrão.
